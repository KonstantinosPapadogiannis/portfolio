# Internationalization

## Languages

Primary/default:
- English

Secondary:
- Greek

English has no locale prefix.

English routes:
- `/`
- `/work/thesis`
- `/work/ergohub`
- `/work/openstack`
- `/work/cuda`
- `/work/computer-vision`
- `/work/energy-data-mining`
- `/resume`

Greek:
- `/el`
- `/el/work/thesis`
- `/el/work/ergohub`
- `/el/work/openstack`
- `/el/work/cuda`
- `/el/work/computer-vision`
- `/el/work/energy-data-mining`
- `/el/resume`

Prefer a maintainable App Router-compatible solution such as `next-intl`.

## Language switcher

Approved treatment:
- globe icon
- `EN · ΕΛ`

Optional very small flags may accompany text, but never use flag-only switching.

Switching language must preserve the current route.

Example:
`/work/thesis` <-> `/el/work/thesis`

Do not send visitors back to home when changing language.

## English quality

English must read as excellent professional software-engineering English.

Use consistent British/international spelling where appropriate:
- organisation
- authorisation
- digitisation
- virtualisation

Use correct terminology:
- backend engineering
- distributed systems
- application layer
- smart contracts
- chaincode
- private data collections
- browser-side transaction signing
- CI/CD pipelines
- state transitions
- cloud infrastructure
- object detection
- validation accuracy

## Greek quality

Greek is not a literal machine translation.

Write natural modern Greek suitable for a Greek software developer audience.

Keep established technical/product terms where natural:
- Backend
- DevOps
- CI/CD
- Hyperledger Fabric
- chaincode
- Docker
- Kubernetes
- React
- TypeScript
- Spring Boot
- REST
- gRPC
- JWT
- Git/GitHub
- CUDA
- OpenStack
- PyTorch

Use natural Greek terms when they are standard:
- distributed systems -> κατανεμημένα συστήματα

Do not force awkward translations.

## Content architecture

Short UI strings:
- locale message dictionaries

Long case studies:
- locale-specific MDX/content files

Avoid conditionals like:
`locale === "el" ? ... : ...`
scattered throughout components.

## SEO

Each locale needs:
- correct `lang`
- localized title/description
- own canonical URL
- hreflang `en`, `el`, `x-default`
- x-default points to English
- Greek pages must not canonicalize to English

## Implementation notes

### Routing

`next-intl` 4, configured in `src/i18n/routing.ts`; `src/proxy.ts` rewrites
unprefixed English URLs internally (`/resume` → `/[locale]=en/resume`).

- The URL alone decides the language (`localeDetection: false`). `/` is
  English for every visitor, whatever the browser language or an earlier
  visit to `/el`; a link to the English page opens in English for everyone.
  No locale cookie is set (`localeCookie: false`). Automatic redirects by
  browser language are also what Google advises against for multilingual
  sites.
- `/en` and `/en/...` redirect (307) to the unprefixed URL; `/el/` redirects
  (308) to `/el`.
- `experimental.optimisticRouting` is off in `next.config.ts`. It cannot
  see the proxy rewrite and, after learning `/[locale]` from `/el`, predicts
  `/resume` as a locale called "resume"; the prefetch then fails with 404.
- The language switcher links to the canonical URL of the same page in the
  other language (`getPathname` + `next/link`), so `/resume` ↔ `/el/resume`
  with no redirect hop. It is not prefetched.
- Section links in the header are plain anchors to the locale's homepage:
  `/#about`, `/el#about` (see design-system-extracted.md §6.1).

### Metadata

- `<html lang>` is the route locale. Titles and descriptions come from
  `content/<locale>/messages.json`.
- Every page sets its own canonical, `hreflang` `en` / `el` and `x-default`
  (English), built with `getPathname`, so Greek pages canonicalise to
  themselves.
- `sitemap.xml` lists each language version of each public page (`/`,
  `/el`, `/resume`, `/el/resume`, `/work/thesis`, `/el/work/thesis`,
  `/work/ergohub`, `/el/work/ergohub`, `/work/openstack`,
  `/el/work/openstack`, `/work/cuda`, `/el/work/cuda`,
  `/work/computer-vision`, `/el/work/computer-vision`,
  `/work/energy-data-mining`, `/el/work/energy-data-mining`) with the same
  alternates. Add new
  public pages to `src/app/sitemap.ts`. QA routes are never listed and are `noindex`.

### Typography by language

The typeface follows the `lang` attribute, not the route (full table in
design-system-extracted.md §4.1):

- English: Geist, labels in IBM Plex Mono.
- Greek: Inter for text and labels. Geist and Plex Mono have no Greek.
- Any Greek text must sit inside an element with `lang="el"`, including a
  Greek fragment on an English page; English inside a Greek page needs
  nothing, Inter covers Latin.
- Write Greek in sentence case in the dictionaries and let
  `text-transform: uppercase` produce capitals. With `lang="el"` the browser
  removes the tonos (`Σχετικά` → `ΣΧΕΤΙΚΑ`), which is correct Greek; typed
  capitals would keep the wrong accents or lose them in sentence case.
- Do not set Greek prose in monospace.
